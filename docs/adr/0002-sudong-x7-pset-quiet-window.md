# 速动 X7 程序号下发等待设备静默窗口

速动 X7 无应用层握手；控制器在发出拧紧结果后约 1 秒内不处理上位机指令，且该状态不会因 TCP 重连清除。因此 PSet 下发前等待「距最近一次拧紧结果与最近一次指令发送均超过 1200ms」，并用命令闸门保护发送瞬间；而不是继续加码「断连重连」重试。选择 X7 专属 + ini 可调（0 可关闭），因为 PF/FIT 没有此行为，且现场可用 ini 做 A/B 与微调。

**Status:** accepted

## Considered Options

- **继续加强重连重试**：日志证明 2,788 次重连全部正确执行（新连接、接收循环先启动、无双重连接），失败发生在 socket 之上；重连无法重置设备侧的指令处理状态。
- **改协议 / 要求固件回显程序号**：协议不可修改（现场约束）。
- **对所有控制器统一加静默窗口**：PF/FIT 无此行为，会增加无谓延迟并影响既有重试时序；故只对 X7 生效。

## Consequences

- X7 每次程序号切换最多增加约 1.2s 延迟，换取首次下发成功率从 9% 提升到接近 100%
- `pset_quiet_window_ms = 0` 可关闭该行为，便于现场 A/B 对比
- 若未来固件修复了忙碌窗口，可将该值调小或移除本机制
