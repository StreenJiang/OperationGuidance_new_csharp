# Merge v1.6.x into v2.2.x — 设计文档

> 2026-06-26，经 grill-with-docs 审查后定稿

## 目标

将 v1.6.x 分支的 33 个 commits 全部合并到 v2.2.x，以单一 merge commit 完成。

## 核心原则

| 优先级 | 原则 | 说明 |
|---|---|---|
| 1 | v1.6.x 技术修复覆盖 v2.2.x | bug 修复、GDI+ 安全、并发优化、DB 幂等性等以 v1.6.x 为准 |
| 2 | v2.2.x 业务增量保留 | SCII XT、新站点、Channel 消息队列、Storage Panel 等新功能保留 |
| 3 | 两边独立新功能共存 | 各自新增互不冲突的逻辑，都保留 |
| 4 | 同一 commit 混合修复+业务 → 拆开逐行判断 | 不按 commit label 整体取，以实际代码语义为准 |
| 5 | 无法判定时暂停 | 列出两边逻辑差异，由用户决策 |

## 执行流程

1. `git stash` — 保险暂存
2. `git merge v1.6.x` — 执行合并
3. 冲突文件分批分析：高风险 → 中风险，每批列出建议裁决 + 依据，用户批量确认
4. v1.6.x 独有改动的核心文件（如 ToolTask.cs）快速扫一眼确认自动合并正确
5. `dotnet build` — 编译验证
6. `dotnet test` — 运行已有测试
7. 输出手动验证清单
8. 暂停，用户自己检查 `git diff --cached`，手动 commit

## 冲突展示方式

分批进行：
1. **高风险批次**：逐个详细分析，每文件标注建议裁决 + 依据
2. **中风险批次**：同样逐个分析
3. 用户可以批量同意或逐个反驳

## 回滚

- 冲突解决过程中：`git merge --abort` 干净回滚
- 冲突解决后 commit 前：`git reset --hard HEAD`
- commit 后：`git reset --hard HEAD~1`

## 验证标准

1. `dotnet build` 编译通过，零错误
2. `dotnet test` 已有测试通过（含 v1.6.x 新增的 ToolTask 测试）
3. 冲突已全部解决（`git status` 无未解决冲突）
4. 手动验证清单已输出
